# Current Strategy

Canonical strategy as of 2026-05-21.

## Core Outcome

This is not an immediate-placement scramble. The current phase is a structured training and interview-calibration period.

Applications during this phase are for:
- practice reps
- market signal gathering
- industry literacy
- narrative refinement
- UI compliance
- confidence building

## Target Identity

Primary positioning:
- junior-to-mid simulation / modeling software engineer
- C++ focused systems engineer

Not the target:
- embedded automotive process-heavy roles
- pure backend CRUD work
- pure data science / ML roles
- gameplay-first game programming roles

Working identity:

> Systems-first engineer who builds and debugs complex, emergent simulations.

## Strategic Career Path

Near-term path:

`systems C++ -> simulation -> real-time systems -> autonomy -> AI`

This repo should support that path rather than distract from it.

## Role Taxonomy

### A - Target

High-signal, compounding roles likely to reinforce the long-term direction.

Examples:
- Simulation Engineer
- Modeling & Simulation Engineer
- Physics Simulation Engineer
- Simulation Software Engineer
- Real-Time Simulation Engineer
- Systems Modeling Engineer
- Computational Modeling Engineer

### B - Stretch / Recon

Roles used to calibrate the next skill plateau and expose vocabulary or tooling gaps.

Examples:
- Digital Twin Engineer
- HPC Software Engineer
- Autonomous Systems Simulation Engineer
- Modeling & Analysis Engineer
- Scientific Computing Engineer

### C - Compliance

Roles used to maintain UI activity requirements while keeping time cost low.

Rules:
- low customization
- low emotional investment
- fast logging in the tracker

## Guardrails

- Protect training time.
- Do not let job search replace C++ growth.
- Do not over-customize resumes.
- Do not chase perfect matches.
- Log every meaningful application.

## Energy and Fit Signals

Good signals:
- simulation
- real-time systems
- physics
- performance
- modeling
- rendering
- systems reasoning
- distributed behavior

Avoid or de-prioritize:
- ADAS production tuning
- ASPICE-heavy environments
- bureaucracy-first roles
- pure business workflow software

## Current Portfolio Anchor

The portfolio anchor is a deterministic simulation-focused project.

Desired properties:
- clear architecture
- deterministic behavior
- performance awareness
- structured debugging
- technical writeups and demo artifacts

Game development is only useful here when it supports simulation depth rather than replacing it.

## What This Phase Should Teach

- what simulation teams actually probe for
- realistic salary and level expectations
- which gaps create interview risk
- which parts of the narrative resonate
- where the project should be extended next
