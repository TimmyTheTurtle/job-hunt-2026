# APPLICATION WORKFLOW FOR CODEX

Use this workflow whenever helping Dorian with a job application.

## Step 1: Capture the exact posting reference

Before doing deeper application work, record:
- the exact job posting URL
- the company name
- the role title

Store the exact posting URL in the application's `job_description.md`.
This matters for UI audit trail and application recordkeeping.

## Step 2: Read the role carefully

Identify:
- actual responsibilities
- true seniority
- required technologies
- domain context
- likely pain points

## Step 3: Evaluate fit

Use ROLE_EVAL_CHECKLIST.md.
Decide whether the role is:
- strong target
- good pragmatic target
- backup target
- weak target
- avoid

## Step 4: Choose the positioning angle

Pick the most credible identity for this role, such as:
- systems-oriented software engineer
- practical business software engineer
- implementation/solutions engineer
- C++ / simulation growth candidate
- technical generalist with strong systems instincts

## Step 5: Select relevant evidence

Choose only the most relevant parts of Dorian's background.
Do not dump everything.

## Step 6: Draft materials

As needed, produce:
- tailored resume bullets
- cover letter
- recruiter message
- short why-this-role statement
- interview prep notes

## Step 7: Truthfulness audit

Check every claim.
Remove anything inflated, vague, or unsupported.

## Step 8: Strategy audit

Ask:
- Does this application support Dorian's broader plan?
- Is the role useful enough to justify the time?
- Does the narrative remain coherent?

## Default output order

1. fit assessment
2. best positioning angle
3. resume tailoring suggestions
4. cover letter draft
5. optional recruiter/short-form variant
